The Instruction
Cycle

How a processor gets one instruction from memory, understands it, runs it, and moves on to the next.

By Imran Lateef

The big pictureOne instruction = a short repeating loop

📥

Fetch

Read the next instruction from memory into the processor.
⚙️

Execute

Interpret the opcode and perform the indicated operation.
🔔

Interrupt

If enabled and one has occurred: save the current state and service the interrupt.

Plus one extra stage: Indirect. If an operand uses indirect addressing, the processor must first fetch the operand's real address from memory.

Figure 14.4The instruction cycle

  1. Fetch reads the instruction.
  2. Execute performs it. No indirection? Straight here.
  3. Indirect fetches operand addresses first, then Execute.
  4. Interrupt is checked after Execute, then back to Fetch.
  5. Execute → Fetch: the loop repeats for the next instruction.

Figure 14.5  Instruction Cycle State Diagram

Four registers do the workWho holds what

PC

Program Counter
Address of the next instruction.

MAR

Memory Address Register
Address sent out on the address bus.

MBR

Memory Buffer Register
Data just read from, or about to be written to, memory.

IR

Instruction Register
The instruction currently being run.

Figure 14.6Data flow: fetch cycle

  1. PC → MAR: address of the next instruction.
  2. MAR puts the address on the address bus.
  3. Control unit requests a memory read.
  4. Memory answers on the data bus into MBR.
  5. MBR → IR: instruction is ready.
  6. Meanwhile PC + 1 prepares the next fetch.

Figure 14.7Data flow: indirect cycle

  1. Rightmost N bits of MBR (the address reference) → MAR.
  2. MAR sends the address on the address bus.
  3. Control unit requests a memory read.
  4. The operand's real address arrives in MBR.

The odd one outExecute takes many forms

🔀

Move data

Transfer data between registers.
💾

Memory or I/O

Read from or write to memory or an I/O device.
🧮

Use the ALU

Invoke the arithmetic logic unit.

Which one happens depends on the opcode in the IR. Fetch, indirect and interrupt are simple and predictable; execute is not.

Figure 14.8Data flow: interrupt cycle

  1. PC → MBR: save where we were.
  2. Control unit loads MAR with the reserved save location (e.g. a stack pointer).
  3. Address bus + data bus + write: MBR is stored in memory.
  4. Control unit loads PC with the interrupt routine's address. The next fetch starts there.

Figure 14.9Two-stage instruction pipeline

  1. (a) While Execute works, Fetch grabs the next instruction. This is prefetch (fetch overlap).
  2. (b) The real picture is less perfect.
  3. Wait: execute usually takes longer than fetch, so stages stall.
  4. New address: after a conditional branch, the next address is unknown until execute finishes.
  5. Discard: fetch guesses "next in memory". Branch taken? Throw it away.

Remember thisSummary

  1. Fetch → Indirect (if needed) → Execute → Interrupt check → repeat.
  2. PC, MAR, MBR and IR move addresses and data over the buses.
  3. Fetch, indirect and interrupt are simple; execute depends on the opcode.
  4. Pipelining overlaps fetch and execute, but waits and branches limit the speed-up.
